# Поиск пятен на кадрах MAR2300

Локальный проект на Python для обработки кадров нейтронного детектора. Он читает кадры, сопоставляет точки DRX с пикселями, обучает модель и выгружает кандидатов на пятна в `.drx`.

## Графический интерфейс

Установите проект с PyTorch и запустите приложение из папки проекта.

```bash
python -m pip install -e '.[ml]'
mar-spots-gui
```

Интерфейс использует Tkinter. Проверьте его командой `python -m tkinter`. Если тестовое окно не открывается, установите пакет Tk для своей сборки Python, например `tk` в Arch Linux или `python3-tk` в Debian и Ubuntu.

1. Нажмите **Открыть кадр…** для одного файла `.mar2300` или **Открыть папку…** для всех кадров одной серии.
2. Выберите файл весов SpotCNN. Если в папке запуска есть `spotcnn.pt` или веса лежат в `runs/live-demo/` либо `runs/received-baseline/`, они подставятся автоматически. Для первого запуска оставьте устройство `cpu`. При наличии калибровки для этой съёмки добавьте её JSON.
3. Нажмите **Найти пятна**. Для серии переключайте кадры над изображением. Выберите кандидата в таблице или нажмите на метку. Двойной щелчок по строке покажет увеличенный фрагмент.
4. Нажмите **Сохранить DRX…**, чтобы записать результаты всех обработанных кадров в один файл.

На вкладке **Инструменты** доступны сведения о кадре, проверка DRX и разметки, экспорт точек MVView, калибровка, импорт разметки, обучение и оценка модели. Отчёт можно сохранить в JSON. Для запуска сразу с выбранными файлами передайте `mar-spots-gui путь/к/кадру.mar2300 --checkpoint путь/к/spotcnn.pt`.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
mar-spots inspect data/sample.mar2300
mar-spots validate data/frames.jsonl
```

`inspect` показывает размеры, тип исходных отсчётов, минимум, максимум и заголовок. FabIO читает кадр как MAR345. При чтении интенсивность, ориентация и размер кадра сохраняются.

`validate` проверяет, что кадры декодируются, точки лежат в пределах кадров, один кадр встречается один раз, а все кадры одного эксперимента находятся в одной выборке.

## Поиск пятен и экспорт серии

```bash
python -m pip install -e '.[ml]'
mar-spots detect-drx data/received/Co runs/received-baseline/spotcnn.pt runs/co-detected.drx --limit 10
mar-spots inspect-drx data/received/Co runs/co-detected.drx --verify-pixels
```

`detect-drx` принимает один кадр или папку с одной серией. Кадры в папке должны иметь общую длину волны и разные средние углы φ. Команда сохраняет один DRX и показывает в JSON число записей по каждому кадру. При нуле кандидатов файл содержит только длину волны. Для повторного запуска выберите новое имя файла.

По умолчанию `detect-drx` учитывает яркость пятна относительно окрестности вместе с оценкой CNN. `--ranking cnn` использует только оценку модели. `--limit` ограничивает число кандидатов на кадр, а `--min-score` задаёт нижнюю границу оценки. Подбирайте границу на проверенных кадрах с пятнами и без пятен при одинаковом `--ranking`. Оценка модели служит для отбора кандидатов и не является вероятностью. Четвёртый столбец DRX содержит исходный отсчёт в центральном пикселе кандидата, как в образце MVView.

DirAx 1.17 прочитал все 410 записей из прогона примера Co выше. `inspect-drx --verify-pixels` сопоставил их с исходными кадрами без расхождений интенсивности.

## Проверка геометрии и выгрузка DRX

Пример ниже использует присланную папку в «Загрузках». Команда выгружает пять точек, вручную выбранных на кадре Ni в MVView.

```bash
archive="$HOME/Downloads/Архив WinRAR"
mkdir -p runs
mar-spots export-drx "$archive/Ni_0Theta_220Dist_1800Exp_001.mar2300" runs/ni.drx \
  --offset-mm 0 -1.5 \
  --point 1150 1150 --point 1152 2296 --point 1182 10 --point 2295 1153 --point 9 1120

mar-spots inspect-drx "$archive/arctit" "$archive/arctit/arktit_.drx" > runs/arctit.json
```

- В `export-drx` координаты берутся из MVView. Точка `1 1` соответствует нижнему левому пикселю. Четвёртый столбец содержит значение этого пикселя, как в примере Ni. Для повторного запуска укажите новое имя выходного файла.
- `--offset-mm` задаёт поправки, которые прибавляются к координатам на детекторе. Для серии `arctit` подошли нулевые поправки, это значение по умолчанию.
- `inspect-drx` сопоставляет строки DRX с кадрами одной серии по среднему углу φ, возвращает точки в координатах массива `[столбец, строка]` и сравнивает пересчитанные векторы отражения с исходными. Пустой список здесь означает, что в DRX нет строки для этого кадра. Полнота разметки проверяется отдельно.
- Геометрия проверена при нулевых χ и ω на двух наборах с положениями детектора `TWOTHETA=0°` и `70°`. Понадобится дополнительный контрольный кадр для поддержки ненулевых χ и ω.

Если есть контрольный кадр, порядок точек из MVView и его DRX, поправку можно вычислить и сохранить в JSON. На кадре Ni команда вычисляет `[0, -1.5]` мм.

```bash
mar-spots calibrate-offset "$archive/Ni_0Theta_220Dist_1800Exp_001.mar2300" \
  "$archive/Ni_0Theta_220Dist_1800Exp_.drx" \
  --point 1150 1150 --point 1152 2296 --point 1182 10 --point 2295 1153 --point 9 1120 \
  > runs/ni-calibration.json
```

Передайте этот файл через `--calibration runs/ni-calibration.json` в `detect-drx`, `export-drx` или `inspect-drx` для кадров с той же калибровкой детектора. Правило расчёта поправок по комментариям `delta` и `detzero` нужно уточнить у НИИ.

## Внутренний формат разметки

JSONL с одной записью на кадр. Путь к кадру можно указать относительно манифеста. Точки заданы как `[x, y]`, где `x` — столбец, `y` — строка, а `[0, 0]` — центр верхнего левого пикселя. Поле `complete: true` обозначает проверенную полную разметку. Без этого поля пустой список означает, что отсутствие пятен проверено, а для непустого списка полнота не установлена. При импорте из DRX в манифест попадают кадры с отмеченными точками, полнота которых неизвестна.

```jsonl
{"image":"sample.mar2300","experiment":"run-a","split":"train","points":[[115.5,204],[312,400]]}
{"image":"background.mar2300","experiment":"run-b","split":"validation","points":[],"complete":true}
```

Поддерживаются `train`, `validation` и `test`. В идентификаторе эксперимента нужно объединять зависимые кадры по согласованному с НИИ признаку, например по одной серии съёмки. Файлы с реальными кадрами и разметкой удобно держать в `data/`, которая исключена из Git.

## Нейросетевая основа

`SpotCNN` принимает нормализованные фрагменты кадра размерности `[N, 1, H, W]` и выдаёт логиты для каждого пикселя. `point_target` строит бинарную карту по размеченным центрам с настраиваемым радиусом. `spot_loss` вычисляет взвешенную бинарную кросс-энтропию, чтобы учесть редкость положительных пикселей. В первом прогоне используются фрагменты 32 × 32 пикселя, логарифм отсчётов и радиус цели 2 пикселя. Модель видит фрагменты вокруг отмеченных точек и фоновые фрагменты, выбранные вдали от отметок. В последних могут встречаться неразмеченные пятна.

## Обучение на присланном архиве

В архиве `data.rar` 15 серий и 1 408 кадров. Следующие команды воспроизводят разбиение первого прогона. Для обучения берутся серии арктита и NH₄Cl, для валидации — NH₄Br(24), для теста — Co, Co2 и проверенный участок TGS60.

```bash
python -m pip install -e '.[ml]'
mkdir -p data/received runs/my-training
bsdtar -xf "$HOME/Downloads/data.rar" -C data/received

mar-spots import-drx data/received data/received-frames.jsonl \
  --train 'NH4Cl(3)' 'NH4Cl(4)' 'NH4Cl(8)' 'NH4Cl(26)' \
    arctit30 'arctit30(1)' arctit60 'arctit60(2)' arctit64 \
  --validation 'NH4Br(24)' --test Co Co2 TGS60 \
  --phi-range TGS60 0 20 --allow-missing > runs/my-training/import.json

mar-spots validate data/received-frames.jsonl
mar-spots train data/received-frames.jsonl runs/my-training/spotcnn.pt --device mps
mar-spots evaluate data/received-frames.jsonl runs/my-training/spotcnn.pt --device mps
mar-spots evaluate data/received-frames.jsonl runs/my-training/spotcnn.pt --device mps --split test --ranking contrast --details
mar-spots predict data/received/Co/Co_001.mar2300 runs/my-training/spotcnn.pt --device mps
```

На системе без MPS можно использовать `--device cpu` или `--device cuda` при наличии CUDA. Для повторного прогона укажите новые имена манифеста и файла весов.

`import-drx` сверяет интенсивность выбранного пикселя с интенсивностью в DRX. Для присланной разметки координаты на половине пикселя округляются к большему индексу. В `arctit60(2)` пять записей относятся к двум отсутствующим кадрам. Кадры TGS60 при φ от 0° до 20° дали 94 совпадения из 94. В остальной части TGS60, а также в `TGS30` и `NH4Br20` интенсивности систематически расходятся, поэтому эти данные остались вне манифеста.

`evaluate` подбирает взаимно однозначные совпадения в рамках `--match-radius-px` (по умолчанию 5 пикселей) и считает полноту поиска среди первых 25 и 100 кандидатов. Ложные срабатывания и точность считаются по кадрам с полной разметкой. `--details` показывает пропущенные точки по кадрам, а для полностью размеченных кадров также лишние кандидаты.

На весах первого прогона включение `--ranking contrast` дало 31 из 48 совпадений на валидации и 119 из 221 на тесте среди первых 100 кандидатов. При `--ranking cnn` результат составил соответственно 25 из 48 и 114 из 221. Оставшиеся вопросы собраны в [QUESTIONS.md](QUESTIONS.md).
